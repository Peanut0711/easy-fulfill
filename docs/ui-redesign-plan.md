# GUI 전면 디자인 개편 계획 (커스텀 테마)

작성: 2026-11-18, 기준 커밋 `872dbcd`(앱 버전 `0.0.26`, `main`). 작업 브랜치 `feat/ui-redesign`. 줄 번호는 작업 중 바뀌므로 함수 이름으로 찾는다. 디자인 규칙은 [UI 디자인 가이드](ui-design-guide.md)에 둔다.

## 정한 것 (2026-11-18, 사용자)

| 항목 | 결정 |
|---|---|
| 방향 | **전면 커스텀 테마.** Windows 기본 모양 대신 앱 전체에 한 가지 테마를 입힌다. 사용 편의(읽기 쉬움, 누르기 쉬움, 키보드 사용, 다음 동작이 보임)를 모양보다 앞에 둔다 |
| 구조 분리 | **포함.** `easy-fulfill.py`의 화면 코드를 탭별 모듈로 나눈 뒤 디자인을 바꾼다 |
| 배치 변경 범위 | **전부 바꿔도 됨.** 버튼 위치·구획·탭 안 배치를 다시 짠다. 기능과 단축키는 그대로 둔다 |
| 브랜치 | `feat/ui-redesign`에서 모두 끝낸 뒤 `main`에 한 번에 합친다 |
| 앱 버전 | 브랜치 커밋에서는 `APP_VERSION`을 올리지 않는다. 각 커밋의 변경은 아래 「버전 이력 초안」에 모으고, `main`에 합치는 커밋에서 한 번 올린다(`AGENTS.md` 예외 조항). `MIN_COMPATIBLE_VERSION`은 올리지 않는다(시트 쓰기 방식은 바꾸지 않음) |

이전 계획의 규칙 중 이 계획이 바꾸는 것: 4단계 계획 4-1의 「스타일시트는 속성 선택자만 쓴다」는 2단계에서 테마로 대체한다.

## 바꾸지 않는 것

- 기능, 시트·API 호출, 파일 형식, 확인 창이 지키는 실제 동작(우체국 접수·인쇄, 발송처리, DB 동기화)과 그 테스트(`tests/test_api_menu.py` 등).
- 단축키(Ctrl+1~6, Ctrl+O 등)와 메뉴 QAction. 메뉴 이름·위치는 바꿀 수 있지만 QAction의 objectName과 단축키는 유지한다.
- 위젯 objectName. 테스트·설정 저장·메뉴가 이름으로 찾는다. 위젯을 새로 만들어 바꿔도 같은 이름을 준다. 이름을 바꿔야 하면 그 이름을 쓰는 곳(`grep`)을 같은 커밋에서 고친다.
- 크기 예산의 원칙(FHD 125%에서 기본 창에 다 보임). 수치는 2단계에서 글꼴을 정한 뒤 다시 정할 수 있다.

## 현재 상태 (0단계 캡처 기준)

`tools/capture_screens.py`로 `872dbcd`를 배율 100·125·150%에서 찍은 결과(배율마다 28장: 탭 6, 설정 페이지 6, 알림·오버레이 5, 메뉴 5, 대화상자 6).

- **구획 표현 3가지:** 주문·발송은 파란 번호 제목, 단건 송장·설정·문서 만들기는 QGroupBox, 상세페이지는 QGroupBox에 ①②③. 문서 만들기 안에서도 QGroupBox와 맨 라벨(「품목」)이 섞여 있다.
- **버튼 규칙 없음:** primary만 padding이 있어 옆 버튼보다 크다. 상세페이지 버튼은 폭을 나눠 늘어나고 다른 탭은 글자 폭이다.
- **125%에서 겹침:** 기본 창(721×638)에서 주문·발송 ① 패널 버튼 줄이 겹친다(「주문 불러오기」가 「복사」를 덮고 「우체국 접수 엑셀」이 「초기화」에 가려짐). 실제 125% PC에서도 같은지 확인이 남아 있다(`docs/known-risks.md`).
- **빈 공간·폭:** 단건 송장·상세페이지는 아래 절반이 비고, 설정 페이지는 내용 폭이 고정돼 오른쪽이 빈다.
- **빈 상태:** 주문·발송은 안내 문구가 있고 배송추적은 빈 표만 보인다.
- **표 머리글:** 문서 만들기는 굵게, 배송추적은 보통.
- **직접 지정한 색:** `setStyleSheet` 약 25곳(시작·작업 중 오버레이, 상태바, 문서 표, 상세 편집기 칩, 끌어다 놓기 테두리), `QFont` 직접 지정 여러 곳.
- **화면 생성 방식 3가지:** `ui/main_window.ui`(QUiLoader), 코드 생성(`_mount_detail_page_tab`, `_mount_quick_excel_inline`, 설정 페이지 일부), 별도 위젯 클래스(`ui/order_ship_panel.py`, `documents/quotation_statement_widget.py`). 쓰지 않는 생성 파일 `ui/main_window.py`, `ui/main_window_ui.py`.
- **큰 파일:** `easy-fulfill.py` 11,649줄 중 `MainWindow`가 약 8,350줄이다. 배송추적만 `tracking/controller.py`(`TrackingController`, 위임 메서드)로 나뉘어 있다.

## 단계

각 단계는 하위 작업마다 따로 커밋한다. 커밋마다 테스트 전체(`python -m unittest discover`)와 캡처 비교를 하고, 브랜치에 푸시한다.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **0. 기준선** | 캡처·비교 도구, 이 계획, 디자인 가이드 초안, `AGENTS.md` 브랜치 버전 예외 | 같은 커밋을 두 번 찍으면 모두 같음 |
| **1. 구조 분리** | 화면 코드를 탭별 모듈로 옮김(모양·동작 그대로) | 1단계 시작 전 캡처와 **모든 장이 같음**(`--fail-on-diff`), 테스트 전체 통과 |
| **2. 테마 기반** | 디자인 기준값(색·글꼴·간격·모서리), Fusion 스타일 + 앱 전체 스타일시트, 직접 지정 색 제거 | 모든 화면이 테마로 그려짐, 크기 예산 통과, **사용자 확인(검토 지점 A)** |
| **3. 공통 부품** | 구획 카드, 버튼 줄, 입력 격자, 빈 상태, 표 설정, 대화상자 버튼 | 부품 단위 테스트, 부품 견본 캡처 |
| **4. 탭별 재디자인** | 주문·발송 → 배송추적 → 단건 송장 → 문서 만들기 → 상세페이지 → 설정 → 메뉴·상태바·알림·대화상자 | 탭마다 전후 캡처, 크기 예산, 125·150%에서 겹침·잘림 없음 |
| **5. 마무리** | 직접 지정 색 재발 방지 테스트, 문서 정리, 실제 PC 확인 목록, 버전 올리기 | **사용자 확인(검토 지점 B)** 뒤 `main`에 합침 |

### 0단계. 기준선

- `tools/capture_screens.py`
  - 캡처: `python tools\capture_screens.py [--scales 100,125,150] [--out 폴더] [--groups tabs,settings,states,menus,dialogs]`. 기본 결과 폴더는 `captures/<커밋>/`(저장소에 넣지 않음)이고 `index.html`로 한눈에 본다.
  - 비교: `python tools\capture_screens.py --compare 전 후 [--fail-on-diff]`. 전·후·차이(바뀐 화소 빨강) 표를 `index.html`로 만든다.
  - 창은 화면에 띄우지 않고, 배율은 장치 픽셀 비율로 그려 흉내 낸다. 창 크기는 배율별 FHD 작업 영역에서 앱이 정하는 기본 크기다(100% 900×800, 125% 721×638, 150% 667×526).
  - PC마다 결과가 달라지지 않게 고정하는 것: 작업 폴더(임시), Google(막고 「연결됨」), 앱 버전(`0.0.0`), 문서 날짜(2026-01-05), 쿠팡 로그인 정보(「판매자」), 배송추적 목록(빈 목록), 백그라운드 작업 끝날 때까지 대기. 구조 분리로 도구가 고치는 메서드(`_detail_session_label`, `_quick_output_dir`, `_load_tracking_list`) 이름이 바뀌면 도구도 함께 고친다.
- 기준선 캡처는 저장소에 넣지 않는다. 필요하면 `git worktree add ..\ef-base 872dbcd`로 기준 커밋을 따로 받아 그 폴더에서 도구를 실행해 다시 만든다(도구는 이 브랜치의 것을 복사해 쓴다).

### 1단계. 구조 분리 (모양·동작 그대로)

목표는 디자인을 바꿀 때 한 탭의 화면 코드가 한 파일에 모여 있게 하는 것이다. 로직을 고치지 않고 **옮기기만** 한다.

- 1-1. 쓰지 않는 `ui/main_window.py`, `ui/main_window_ui.py` 삭제(어디서도 import하지 않는지 `grep`으로 확인).
- 1-2. `MainWindow` 메서드를 영역별로 묶어 `ui/main/` 아래 믹스인 클래스로 옮긴다: `order_ship.py`(주문·발송, 송장·발송 파일), `quick_invoice.py`, `documents.py`, `detail_page.py`, `settings.py`(연동·알림·주문·사은품·DB 동기화·프로그램), `chrome.py`(메뉴바·상태바·알림 띠·오버레이·단축키), `startup.py`(시작·종료·창 위치). `MainWindow(QMainWindow, …Mixin)`. 믹스인을 고른 이유: 메서드 이름과 `self.…` 참조가 그대로라 테스트의 `patch.object(MainWindow, …)`와 `TrackingController` 위임이 바뀌지 않는다.
- 1-3. 모듈 수준 작업 함수(`run_*_worker`)와 `QThread` 클래스는 이번 단계에서 옮기지 않는다(화면 디자인과 무관, 별도 작업).
- 하위 작업마다 테스트 전체 + `--fail-on-diff` 캡처 비교. 하나라도 다르면 원인을 찾아 고친 뒤 커밋한다.
- 탭 화면을 `.ui`에서 코드로 옮기는 일은 4단계에서 그 탭을 다시 디자인할 때 한다(1단계에서 하면 모양이 미세하게 바뀌어 「모양 그대로」를 검증할 수 없다).

### 2단계. 테마 기반

- 새 모듈 `shared/theme.py`: 디자인 기준값(가이드의 「기준값」)과 그 값으로 만드는 앱 전체 스타일시트, `apply_theme(app)`(Fusion 스타일, 글꼴, 팔레트, 스타일시트). `main()`과 `tools/capture_screens.py`·`tools/measure_window_sizes.py`가 같은 함수를 부른다.
- Fusion을 쓰는 이유: Windows 11 스타일은 스타일시트를 일부만 따르고 Windows 10·11에서 모양이 달라, 사무실 PC마다 다르게 보일 수 있다. Fusion은 스타일시트를 모두 따르고 어느 PC에서나 같게 그린다.
- `shared/ui_style.py`의 역할·상태 도우미(`set_button_role`, `set_status`, `set_band`)는 이름을 유지하고 색은 테마 기준값에서 가져온다. `tests/test_ui_style.py`의 「속성 선택자만」 검사는 「색 값은 `shared/theme.py`에만」 검사로 바꾼다.
- 직접 지정한 `setStyleSheet`·`QFont`를 테마 규칙(동적 속성 + 선택자)으로 옮긴다. 끌어다 놓기 테두리처럼 상태에 따라 바뀌는 것도 속성으로 바꾼다.
- 글꼴 크기를 정하고(가이드 「글꼴」) `tools/measure_window_sizes.py`로 창·탭 최소 크기를 다시 잰다. 예산을 넘으면 예산을 다시 정할지 배치를 줄일지 검토 지점 A에서 정한다.
- **검토 지점 A:** 테마만 입힌 상태(배치는 그대로)의 캡처 `index.html`을 사용자에게 보이고, 색·글꼴 크기·밀도를 확정한 뒤 3단계로 간다.

### 3단계. 공통 부품 (`shared/ui_components.py`)

가이드 「부품」의 것을 만든다. 탭에 적용하는 것은 4단계다.

- `SectionCard(title, step=None, actions=())`: 구획 하나(흰 카드, 제목 줄, 오른쪽 보조 동작). QGroupBox·파란 번호 제목을 모두 대신한다.
- `ButtonRow`: 왼쪽 보조·위험 동작, 오른쪽 주 동작. 버튼 높이 통일, 좁아지면 줄바꿈 없이 글자 폭 유지(겹침 방지).
- `FormGrid`: 라벨 열 + 입력 열(+ 오른쪽 보조 버튼 열), 필수 표시, 칸 아래 오류 문구.
- `EmptyState(text, action=None)`: 빈 목록·빈 표 안내.
- `setup_table(table, numeric_columns=…)`: 머리글·행 높이·선택 색·숫자 오른쪽 정렬·잘린 칸 툴팁.
- 대화상자 버튼: `QDialogButtonBox` + 동작 이름 버튼(「예」 대신 「접수하기」), 되돌릴 수 없는 동작은 위험 버튼.
- 부품 견본 화면(캡처 도구의 `components` 묶음)을 추가해 부품만 따로 본다.

### 4단계. 탭별 재디자인

탭마다 (1) `.ui` 부분을 코드 페이지 클래스로 옮기며 새 부품으로 다시 짜고(objectName 유지), (2) 전후 캡처를 비교하고, (3) 크기 예산과 125·150% 겹침을 확인한다. 탭 하나가 커밋 1~2개다.

| 순서 | 대상 | 다시 짤 것 (0단계 캡처에서 본 문제) |
|---|---|---|
| 4-1 | 주문·발송 | ①② 패널을 구획 카드로, 버튼 줄 겹침(125%) 해결, 다음 동작 강조 유지, 빈 미리보기·송장 영역을 빈 상태 부품으로, 끌어다 놓기 영역 |
| 4-2 | 배송추적 | 필터·검색·동작 줄 정리, 빈 상태, 표 머리글·열 폭·위험 건수 표시, 마지막 새로고침 시각 |
| 4-3 | 단건 송장 | 입력 격자와 「생성」 위치, 아래 빈 공간, 오늘 만든 목록 |
| 4-4 | 문서 만들기 | 기본정보·상품 찾기·품목·계산 요약 구획 통일, 하단 동작 줄 |
| 4-5 | 상세페이지 | ①②③ 단계 카드, 대상 상품 입력을 단계 안으로, 버튼 폭, 작업 로그 |
| 4-6 | 설정 | 분류 목록, 페이지 폭 정책, 키 행·상태 표시 |
| 4-7 | 공통 틀 | 메뉴바(「API(개발 중)」 이름 정리), 탭바, 상태바 칩, 알림 띠, 시작·작업 중 오버레이 |
| 4-8 | 대화상자 | 우체국 주소 검색, 사은품 설정·집계, 상세 HTML 편집기, 이미지 보기, 확인 창 |

### 5단계. 마무리

- `shared/theme.py` 밖에서 색 값(`#rrggbb`)이나 `setStyleSheet`를 쓰면 실패하는 테스트(허용 목록 없음이 목표).
- 이전 계획 문서(4단계, 창 크기·설정, 알림·상태바)에 「이 계획으로 대체됨」 표시, `docs/known-risks.md` 정리, 실제 PC 확인 목록(`docs/ui-checklist-redesign.md`).
- **검토 지점 B:** 최종 캡처와 확인 목록을 사용자에게 보이고, 한 PC에서 브랜치를 받아 실제 주문 파일로 확인한 뒤 `main`에 합친다. 합치는 커밋에서 `APP_VERSION`을 올리고 「버전 이력 초안」을 [버전 이력](app-version-update-guide.md#버전-이력)에 한 줄로 정리한다.

## 검증

- 커밋마다: `python -m unittest discover`, `python tools\capture_screens.py`와 직전 캡처 비교, 4단계부터는 `python tools\measure_window_sizes.py`.
- 1단계: 비교에서 다른 장이 0이어야 한다.
- 2·4단계: 바뀐 장의 차이 이미지를 보고 의도한 변화만 있는지 확인한다. 커밋 본문에 바뀐 화면과 크기 측정값을 적는다.
- 캡처는 실제 모니터 배율과 글꼴 힌팅이 조금 다를 수 있어, 검토 지점 B 전에 실제 125·150% PC에서 확인한다.

## 버전 이력 초안

`main`에 합칠 때 [버전 이력](app-version-update-guide.md#버전-이력)에 정리할 앱 동작 변경을 커밋마다 여기에 적는다.

- (0단계) 앱 동작 변경 없음. 개발용 화면 캡처 도구 추가.
- (1단계) 앱 동작 변경 없음. 메인 창 화면 코드를 `ui/main/`으로 나눔.
- (2-1) 앱 전체에 새 테마를 입힌다: 회색 바탕에 흰 카드 묶음, 아래 줄로 표시하는 탭, 둥근 버튼·입력칸, 굵은 표 머리글, 키보드 포커스 테두리. Windows 기본 모양 대신 Fusion 스타일로 그려 PC마다 같게 보인다. 주의(주황) 글자를 더 진하게 해 읽기 쉽게 했다.
