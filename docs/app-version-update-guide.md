# 앱 버전과 업데이트 안내

여러 PC(현재 4대)가 같은 공유 Google 스프레드시트에 쓰기 때문에, 업데이트하지 않은 PC가 예전 방식으로 데이터를 덮어쓰지 않도록 앱 버전을 기록하고 낮은 버전의 쓰기를 막는다. 구현은 `sheets/version_gate.py`에 있다.

## 사무실에서 할 일

### 업데이트하는 방법 (각 PC)

1. 앱을 닫는다. 닫을 때 남은 시트 저장을 마저 하므로 창이 닫힐 때까지 기다린다.
2. 소스트리(SourceTree)에서 `easy-fulfill` 저장소를 열고 왼쪽 브랜치에서 `main`을 선택한다.
3. 상단의 **페치(Fetch)**를 누르고 원격 저장소 `origin`을 선택해 완료를 기다린다.
4. 상단의 **풀(Pull)**을 누른다. 원격 저장소 `origin`과 브랜치 `main`을 선택한 뒤 확인을 누른다. [Atlassian의 소스트리 Pull 안내](https://support.atlassian.com/sourcetree/kb/commit-push-and-pull-a-repository-on-sourcetree/)
5. 같은 저장소 폴더의 `run.bat`을 실행하고 타이틀바에서 업데이트된 버전을 확인한다.
6. 시작 확인이 끝나면 공유 시트의 **「PC버전」 탭**에서 그 PC의 버전과 확인 시각을 확인한다.

- Pull이 충돌이나 "로컬 변경 있음"으로 막히면 무리하게 진행하지 말고 개발 담당에게 화면을 보여 준다.
- `requirements.txt`가 바뀐 버전이면 첫 실행 때 패키지 설치로 조금 오래 걸린다.
- 날짜형 버전을 쓰는 PC는 `0.0.1`을 새 버전으로 감지하지 못하므로 이번에는 각 PC에서 직접 업데이트한다.

### 「PC버전」 탭 보는 법

| 열 | 내용 |
|---|---|
| PC | `사용자명@PC이름` |
| 버전 | 그 PC가 마지막으로 기록한 표시 버전(예: `0.0.1`) |
| 마지막 확인 | 그 PC가 마지막으로 버전을 확인한 시각(시작할 때와 실행 중 1시간마다 갱신) |

- 모든 PC가 같은 최신 버전이면 정상이다.
- 탭에 없는 PC는 이 기능이 들어간 버전(2026.11.17.1)보다 오래된 버전이거나, 아직 한 번도 새 버전으로 실행하지 않은 PC다.

### 「새 버전 안내」 창

다른 PC가 더 새 버전을 쓰고 있으면 뜬다. **무시하고 그대로 계속 써도 된다.**

| 버튼 | 동작 |
|---|---|
| 닫기 | 이번 실행 동안 같은 버전은 다시 묻지 않는다. 프로그램을 다시 켜면 또 묻는다. |
| 오늘 더 이상 묻지 않음 | 다시 켜도 오늘은 묻지 않는다. 내일 다시 묻는다. |

- 안내 창을 아예 끄려면 **⚙ 설정 → 「프로그램」 → 「새 버전 안내 무시」**를 켠다(기본 꺼짐, PC마다 따로 저장).
- 안내를 끈 PC는 업데이트를 놓치기 쉬우니 「PC버전」 탭을 가끔 확인한다.
- 실행 중에는 1시간마다 확인하므로, 다른 PC가 업데이트한 뒤 최대 1시간 늦게 뜰 수 있다.

### 「프로그램 업데이트 필요」 창

공유 시트가 요구하는 최소 버전보다 이 PC의 버전이 낮을 때 뜬다. 이때는 **이 PC에서 시트에 쓰는 모든 작업이 멈춘 상태**다(읽기는 된다). 「새 버전 안내 무시」를 켜 두었어도 실행마다 한 번 뜬다.

팝업에 나온 소스트리 페치·풀 절차대로 업데이트하고 다시 실행한다.

## 동작 방식

- 앱 버전은 `APP_VERSION`(예: `0.0.1`)이다. 날짜형 PC 기록은 새 버전 안내의 비교 대상에서 제외한다.
- 공유 「설정」 탭의 `min_app_version` 값이 **공유 최소 버전**이다.
  - `0.0.1`부터 세 자리 버전은 배포된 날짜형 버전보다 새 버전으로 비교한다. 이번 전환에서도 기존 최소 호환 버전 `2026.11.17.1`이 적용된다.
  - 향후 공유 시트 쓰기 방식이 호환되지 않아 최소 버전을 세 자리 버전으로 올리면, 기존 날짜형 앱도 쓰기를 막을 수 있도록 시트에는 `2026.11.18.1.0.0.2`처럼 전환 기준과 최소 버전을 이어 저장한다. 세 자리 버전 앱의 화면에는 `0.0.2`처럼 표시한다. 이 설정은 앱이 관리한다.
- `get_authorized_gspread_client()`가 돌려주는 모든 Google 클라이언트에 쓰기 차단 장치가 씌워진다. 앱의 모든 시트 쓰기와 `database-sync.py` 같은 스크립트가 여기에 해당한다.
  - GET이 아닌 요청(값 쓰기, 행 추가, 탭 추가 등)을 보내기 전에 현재 버전이 공유 최소 버전보다 낮으면 `AppVersionBlockedError`로 막는다.
  - 공유 최소 버전은 10분마다 다시 읽어, 실행 중에 다른 PC가 올린 값도 반영한다.
  - 공유 최소 버전을 다시 읽지 못하면 마지막 확인값을 유지한다. 확인한 값이 없으면 쓰기를 허용한다.
- 시작 3초 뒤와 실행 중 1시간마다(`startup_check`)는 다음을 한다.
  1. 공유 최소 버전이 이 앱의 `MIN_COMPATIBLE_VERSION`보다 낮으면 그 값으로 올린다. 낮추지는 않으며, 값을 비교한 뒤 쓴다.
  2. 「PC버전」 탭에 이 PC의 버전과 시각을 기록한다.
  3. 다른 PC가 더 새 버전을 쓰면 「새 버전 안내」를 띄운다.
- 처음 이 기능이 들어간 버전을 실행하는 PC가 「설정」에 `min_app_version` 행을 추가하고 「PC버전」 탭을 만든다.

### 막을 수 없는 경우

이 장치가 없는 이전 버전(2026.11.17.1 이전)은 코드로 막을 수 없다. 그런 PC는 한 번은 직접 Pull 해야 한다. 그 뒤로는 안내 창과 최소 버전으로 관리된다.

## 버전 올리기 규칙 (개발)

`AGENTS.md`의 「앱 버전 관리」 절과 같다.

- 여러 PC가 `main`을 Pull 해서 쓰므로 `main`에 푸시하는 커밋 하나하나가 배포다.
- 앱 동작 코드(`tests/` 밖의 `.py`, `run.bat` 등)를 바꾸는 커밋에서는 같은 커밋에서 `APP_VERSION`의 세 번째 숫자를 1 올린다(`0.0.1` → `0.0.2`).
  - 이 문서의 버전 이력 맨 위에 날짜, 버전, 변경 설명을 추가한다.
  - 문서, 테스트, 규칙만 바꾸는 커밋은 올리지 않는다.
- 공유 시트에 쓰는 방식이 바뀌어 이전 버전과 함께 쓰면 데이터가 덮어써지거나 깨지는 변경이면, `MIN_COMPATIBLE_VERSION`도 같은 값으로 올리고 커밋 본문에 이유를 적는다.
- 그 밖에는 `MIN_COMPATIBLE_VERSION`을 올리지 않는다. 올린 버전이 한 대에서라도 실행되면 그보다 낮은 모든 PC의 시트 쓰기가 멈춘다. 애매하면 올리기 전에 확인한다.

### 개발 PC 주의

- 운영 시트에 연결된 PC에서 아직 푸시하지 않은 더 높은 버전을 실행하면, 그 버전이 「PC버전」 탭에 기록되어 다른 PC들에 「새 버전 안내」가 뜬다.
- `MIN_COMPATIBLE_VERSION`까지 올린 상태로 실행하면, 다른 PC들은 그 버전을 받을 때까지 시트 쓰기가 막힌다.
- 시험할 때는 운영 시트에 연결되지 않은 환경을 쓰거나, 실행 전에 버전 값을 확인한다.
