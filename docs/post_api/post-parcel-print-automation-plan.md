# 우체국 계약소포 운송장 출력 자동화 구현 계획서

작성: 2026-08-19  
대상: `easy-fulfill` 데스크톱 GUI / 계약고객전용시스템 / OZ Report Viewer

## 1. 목적

계약소포 OpenAPI로 실제 접수된 건만 대상으로, 현재 사용 중인 다음 수동 인쇄 흐름을 안전하게 자동화한다.

```text
실제 접수 성공
  → 계약고객전용시스템 운송장출력
  → 오늘 날짜 + 신규출력 조회
  → 이번 실행의 등기번호만 선택
  → 운송장출력 팝업에서 인쇄
  → OZ Report Viewer 인쇄 아이콘
  → Windows 인쇄창: Xprinter XP-DT108B / 우체국 용지 확인
  → 인쇄
```

운송장을 새로 렌더링하거나 OZ Viewer를 대체하지 않는다. 우체국이 제공하는 운송장 양식·바코드·주소별 배달 정보를 그대로 사용하고, 기존 포털과 Viewer의 조작만 자동화한다.

## 2. 확인된 기준과 범위

### 2.1 확인된 흐름

- `InsertOrder(testYn=N)` 실제 접수 결과가 계약고객전용시스템의 운송장출력 목록에 표시됨을 확인했다.
- API 접수 건은 주문접수명이 `OPEN API`, 출력여부가 `미출력`으로 표시된다.
- 포털에서 인쇄한 API 접수 운송장은 기존 수동 접수 운송장과 동일한 OZ Viewer 양식으로 열린다.
- `printYn=N`을 유지한다. 이는 프로그램이 라벨을 자체 생성하지 않고, 포털의 운송장출력 흐름을 사용한다는 뜻이다.
- 운송장에 표시되는 `0504` 가상전화번호(`vTelNo`)는 우체국이 출력 단계에 부여하는 결과값이며, 접수 요청에서 프로그램이 지정하지 않는다.

### 2.2 포함

- 일반 계약소포의 실제 접수 성공 건을 대상으로 한 단건 인쇄 자동화
- 접수 결과의 등기번호와 포털 행을 정확히 대조하는 기능
- 포털 운송장출력 팝업과 OZ Viewer, Windows 인쇄창의 순차 조작
- 프린터·용지·인쇄 장수 사전 검증과 안전 중단
- 인쇄 시도·Windows 인쇄 명령 전달·포털 출력여부 확인의 분리 기록

### 2.3 제외

- 운송장 PDF·바코드·OZ Viewer 자체 구현
- 포털에서 확인되지 않은 행의 추정 선택 또는 전체 신규출력 인쇄
- 접수와 동시에 네이버 발송처리
- 반품소포, 맞교환, EMS, 다량등기
- 첫 단계의 완전 무인 인쇄 및 다건 인쇄

## 3. 설계 원칙

1. **이번 실행의 등기번호만 출력한다.** `신규출력`은 다른 작업자의 미출력 건도 포함할 수 있으므로 전체 선택을 금지한다.
2. **접수·포털선택·Windows 인쇄·실물 출력은 서로 다른 상태다.** 하나가 성공해도 다음 단계 성공으로 추정하지 않는다.
3. **확인 불가 시 인쇄하지 않는다.** 로그인 상태, 대상 행, Viewer 창, 프린터명, 용지명이 하나라도 불일치하면 즉시 중단한다.
4. **좌표 클릭을 기본 방식으로 삼지 않는다.** 웹은 DOM 선택자, Windows 창은 UI Automation의 창 제목·컨트롤 이름으로 식별한다. 화면 해상도에만 의존하는 클릭은 진단용 최후 수단으로 제한한다.
5. **물리 인쇄 전에는 사용자 확인을 유지한다.** 초기 단계에서는 Viewer가 열리고 인쇄창 설정이 맞는 곳까지 자동화한 뒤 마지막 `확인`은 사용자가 누른다.
6. **인증정보와 개인정보를 로그에 남기지 않는다.** 로그에는 내부 주문 식별자, 등기번호, 단계, 오류 코드·창 제목만 남긴다.

## 4. 사전 준비

### 4.1 PC 환경

- 계약고객전용시스템 로그인 가능한 Chrome 전용 자동화 프로필을 준비한다.
- OZ Report Viewer와 `Xprinter XP-DT108B` 드라이버가 설치돼 있어야 한다.
- 프린터의 인쇄 용지 목록에 `우체국`이 표시되어야 한다.
- 초기 구현용 PC는 단일 모니터·일반 배율(권장 100%)로 고정해 창 탐지 검증을 단순화한다.

### 4.2 설정값

비밀값이 아닌 아래 값만 기존 비공개 `설정` 탭 또는 로컬 인쇄 설정에 저장한다.

| 키 | 예시 | 용도 |
| --- | --- | --- |
| `epost_print_printer_name` | `Xprinter XP-DT108B` | Windows 인쇄창의 목표 프린터명 |
| `epost_print_paper_name` | `우체국` | Windows 인쇄창의 목표 용지명 |
| `epost_print_label_template` | 운영 중인 양식명 | 포털 운송장출력 팝업의 양식 선택 기준 |
| `epost_print_browser_profile` | 전용 자동화 프로필 경로 | 로그인 세션을 유지할 Chrome 프로필 |
| `epost_print_require_final_confirm` | `Y` | 초기 물리 인쇄 전 마지막 확인 유지 |

프린터명과 용지명은 문자열이 완전히 일치해야 한다. 설정값을 찾지 못하면 기본값을 추측하지 않고 중단한다.

## 5. 데이터와 상태

### 5.1 접수 이력

실제 접수 성공 시 다음을 로컬 이력(SQLite 권장)에 저장한다.

| 값 | 출처 | 용도 |
| --- | --- | --- |
| 내부 주문키·주문번호 | 주문/송장 행 | 중복 접수·화면 표시 |
| `reqNo`, `resNo`, `regiNo` | InsertOrder·GetResInfo | 포털 출력 대상 대조 |
| 접수 일시·발송지 코드 | API/설정 | 포털 조회 조건 |
| 접수 상태 | 프로그램 | 접수 성공 여부 |
| 출력 상태 | 프로그램·포털 확인 | 재출력 방지 |
| 인쇄 시도·명령 시각 | 프로그램 | 문제 재현 |

현재의 단건 실접수 확인 기능은 포털 반영 검증 용도이며, 이력 저장과 운영용 중복 차단은 이 단계에서 추가한다.

### 5.2 출력 상태 모델

```text
RECEIPT_CONFIRMED
  → PRINT_TARGET_VERIFIED
  → PORTAL_PRINT_POPUP_OPENED
  → OZ_VIEWER_OPENED
  → PRINT_DIALOG_VERIFIED
  → PRINT_COMMAND_SENT
  → PORTAL_PRINTED_CONFIRMED
```

각 상태 사이에 실패하면 이후 단계를 실행하지 않는다. `PRINT_COMMAND_SENT`는 Windows에 명령이 전달됐다는 뜻일 뿐, 실물 출력 확인은 아니다.

## 6. 모듈 설계

| 모듈 | 책임 |
| --- | --- |
| `post_parcel_receipt_store.py` | 접수·인쇄 이력 저장, 중복·재출력 판정 |
| `epost_portal_session.py` | ID·비밀번호를 저장하지 않는 전용 Chromium 로그인 세션 연결 |
| `epost_portal_diagnostic.py` | 운송장출력 화면의 비개인정보 컨트롤 구조를 읽기 전용으로 수집 |
| `post_parcel_print_portal.py` | Chrome에서 포털 로그인·조회·정확한 행 선택·출력 팝업 열기 |
| `post_parcel_print_desktop.py` | OZ Viewer·Windows 인쇄창 탐지와 프린터·용지 확인 |
| `post_parcel_print_diagnostic.py` | 선택자·창 제목·컨트롤 계층을 읽기 전용으로 기록 |
| `easy-fulfill.py` | 접수 결과 화면, 출력 대상 확인, 사용자 최종 확인, 상태 표시 |

웹 포털은 Selenium 또는 Playwright로 DOM을 제어한다. 기존 사용 중인 Chrome 세션을 직접 탈취하지 않고, 전용 자동화 프로필에서 최초 1회 사용자가 로그인해 세션을 유지한다. OZ Viewer와 Windows 인쇄창은 `pywinauto`의 UI Automation 백엔드로 제어한다.

`epost_portal_session.py`의 로그인 연결 기능은 구현됐다. 이 기능은 `output/epost-browser-profile`과 현재 Windows 사용자만 복호화할 수 있는 DPAPI 보호 세션 백업에 로그인 세션만 저장하며, ID·비밀번호를 프로그램·스프레드시트·Git에 저장하지 않는다. 포털 조회·행 선택·인쇄 기능은 아직 구현하지 않는다.

`epost_portal_diagnostic.py`는 구현됐다. 전용 Chromium 창에서 사용자가 운송장출력 화면으로 이동하면, 버튼·입력칸의 식별 정보만 `output/epost-portal-diagnostic.json`에 보관한다. 화면의 수취인·주소·전화번호·목록 행·입력값은 저장하지 않으며, 조회·행 선택·인쇄도 실행하지 않는다.

## 7. 단계별 구현

### 1단계: 접수 이력과 출력 대상 화면

1. 실제 접수 성공 결과를 SQLite에 저장한다.
2. GUI에 `우체국 운송장 출력` 메뉴를 추가한다.
3. 미출력 접수 이력 중 사용자가 선택한 1건의 주문번호·등기번호·수취인명 일부만 보여 준다.
4. 이미 `PRINT_COMMAND_SENT` 이상인 건은 기본적으로 제외하고, 재출력은 별도 확인을 요구한다.

완료 기준: 프로그램을 재시작해도 이번 접수의 등기번호를 출력 후보로 복원할 수 있다.

### 2단계: 포털 읽기 전용 진단

1. 전용 Chrome 프로필로 계약고객전용시스템 운송장출력 화면을 연다.
2. 오늘 날짜, 발송지, 출력대상 `신규출력` 조건을 입력하고 조회한다.
3. 포털 행에서 등기번호·출력여부·수취인명을 읽는다.
4. 접수 이력의 등기번호와 정확히 일치하는 행만 찾아 결과를 GUI에 보여 준다.

이 단계는 체크박스·운송장출력·인쇄 버튼을 누르지 않는다.

완료 기준: 최근 실제 접수 1건에서 `미출력` 포털 행과 등기번호를 정확히 대조한다.

### 3단계: 포털 출력 팝업 열기

1. 2단계에서 검증한 등기번호 행 1개만 체크한다.
2. 선택 수·등기번호·포털 행 수가 모두 1개인지 다시 검사한다.
3. `운송장출력`을 눌러 팝업을 연다.
4. 설정값의 양식이 선택돼 있는지 확인한다.
5. `인쇄` 버튼 직전에서 멈춰 창 제목과 선택 양식을 GUI에 표시한다.

완료 기준: 실제 인쇄 없이 대상 1건의 운송장출력 팝업을 재현한다.

### 4단계: OZ Viewer 및 인쇄창 검증

1. 사용자가 출력 진행을 승인하면 팝업의 `인쇄`를 누른다.
2. 정해진 시간 내 `오즈 리포트 뷰어` 창이 하나 열렸는지 확인한다.
3. Viewer의 프린터 아이콘을 눌러 Windows 인쇄창을 연다.
4. 다음을 읽고 예상값과 대조한다.
   - 프린터명: `epost_print_printer_name`
   - 용지: `epost_print_paper_name`
   - 페이지·매수: 선택 접수 건수와 일치
5. 모두 일치하면 인쇄창을 연 채로 GUI에 `인쇄 준비 완료`로 표시한다.

완료 기준: 실물 인쇄 없이 인쇄창의 프린터·용지·매수를 자동 검증한다.

### 5단계: 단건 인쇄 명령

1. GUI의 마지막 확인 창에 주문번호·등기번호·프린터·용지·인쇄 매수를 표시한다.
2. 사용자가 승인하면 Windows 인쇄창의 `확인`을 누른다.
3. `PRINT_COMMAND_SENT` 시각을 이력에 기록한다.
4. 사용자가 실물 라벨을 확인한 후 포털을 재조회해 출력여부가 `출력`으로 바뀌었는지 기록한다.

완료 기준: API 실제 접수 1건이 지정 프린터와 `우체국` 용지로 한 번만 출력된다.

### 6단계: 다건 확장

1. 2~3건을 접수한다.
2. 이력과 포털 목록의 등기번호 집합이 정확히 동일한지 확인한다.
3. 누락·추가 행이 있으면 한 건도 선택하지 않고 실패 처리한다.
4. 총 라벨 장수와 Windows 인쇄 매수가 일치할 때만 출력한다.
5. 다른 작업자의 신규출력 건이 섞인 상황을 재현해 제외되는지 확인한다.

## 8. 예외 처리 및 중단 조건

| 상황 | 처리 |
| --- | --- |
| 포털 로그인 세션 만료 | 로그인 화면을 표시하고 사용자 로그인 후 처음부터 진단 재시작 |
| 등기번호 행이 없음 | 인쇄하지 않고 접수 이력·조회 날짜·발송지 확인 안내 |
| 같은 등기번호가 2개 이상 | 인쇄하지 않고 포털 확인 요청 |
| 포털 행이 이미 `출력` | 기본 차단, 재출력 사용자 확인 필요 |
| OZ Viewer 미실행·복수 실행 | 인쇄하지 않고 창 목록을 진단 로그에 기록 |
| 목표 프린터 미선택 | 인쇄하지 않고 프린터 선택 화면 유지 |
| `우체국` 용지 없음 | 인쇄하지 않고 드라이버/용지 설정 안내 |
| 선택 건수와 매수 불일치 | 인쇄하지 않고 다시 조회 |
| 자동화 중 예외 발생 | 가능한 창을 닫지 않고 현재 단계·창 제목·등기번호만 기록 |

## 9. 검증 체크리스트

- [ ] 실제 접수 결과가 재시작 후에도 출력 후보로 남는다.
- [ ] 포털의 `신규출력` 전체가 아닌, 저장된 등기번호만 선택된다.
- [ ] 수동 접수·다른 작업자 미출력 행은 선택되지 않는다.
- [ ] 운송장출력 팝업에서 운영 양식이 확인된다.
- [ ] OZ Viewer 창 제목과 인쇄창이 정확히 탐지된다.
- [ ] 프린터 `Xprinter XP-DT108B`, 용지 `우체국` 불일치 시 인쇄되지 않는다.
- [ ] 단건 인쇄 후 실물 라벨의 바코드·주소·방향이 정상이다.
- [ ] 포털 출력여부 전환과 Windows 인쇄 명령 시각을 구분해 기록한다.
- [ ] 다건에서 대상 등기번호·선택 행·인쇄 매수가 모두 일치한다.

## 10. 구현 시작 전 사용자 확인 항목

1. 자동화 전용 Chrome 프로필을 만들어도 되는지
2. 초기 단계에서 마지막 Windows `확인` 버튼은 사용자가 직접 누를지
3. 목표 프린터명과 용지명이 항상 `Xprinter XP-DT108B` / `우체국`인지
4. 포털 운송장출력 팝업에서 항상 사용할 양식 이름
5. 인쇄 완료 판단을 포털의 출력여부 전환으로 볼지, 실물 라벨 확인까지 요구할지
