# 남은 위험과 버그 수정·반응성 개선 작업 기록

2026-11-18 기준(앱 버전 `0.0.14`, 직전 커밋 `2a3fce6`, 브랜치 `feat/window-settings`). 「easy-fulfill 버그 수정 및 반응성 개선」 작업과 그 후속 수정 이후에 남은 위험과, 작업별 결과를 정리한다.

검증 원칙:

- 각 수정은 문제를 재현하는 테스트를 먼저 만들어, 수정 전 코드에서 실패하는 것을 확인했다.
- 반응성 항목은 같은 조건에서 전후를 재고 중앙값으로 비교했다.
- 우체국 실제 접수와 인쇄, 쿠팡 WING 저장과 검수 요청, 네이버 발송처리 API는 실행하지 않았다.
- 운영 Google 스프레드시트에는 쓰지 않았다. 실서비스 확인은 읽기 전용으로만 했다.

## 1. 직접 해야 하는 것

## 2. 줄였지만 남아 있는 것

| 위험 | 현재 상태 |
|---|---|
| 읽은 뒤 쓰기까지의 틈(M열 관리상태, 주문번호 인덱스, 설정 저장) | Sheets API에는 조건부 쓰기가 없어 읽기와 쓰기 사이(1초 미만)에 다른 PC가 같은 칸을 바꾸면 덮어쓴다. 다시 누르거나 다음 반영 때 복구된다 |
| 문의 폴링 중복 알림 | 선점을 쓴 뒤 2초 기다렸다 다시 읽어 확인한다. 두 PC의 쓰기가 2초 넘게 벌어져 도착할 때만 중복될 수 있다 |
| 버전 차단의 예외 | 공유 최소 버전을 다시 읽지 못하면 마지막 확인값을 유지한다. 확인한 값이 없으면 쓰기를 허용한다 |
| 새 버전 안내 지연 | 실행 중에는 1시간마다 확인하므로 최대 1시간 늦게 뜰 수 있다 |
| 탭 이름 변경 | 캐시한 탭이 없어지면 바로 다시 열어 오류는 나지 않는다. 대신 원래 이름의 빈 탭이 새로 생기고 예전 데이터는 이름을 바꾼 탭에 남는다(캐시 도입 전과 같은 동작). 송장추적·설정·문의알림·PC버전 탭 이름은 바꾸지 않는다 |

## 3. 운영할 때 주의할 것

- **버전 올리기** — `AGENTS.md` 규칙에 따라 앱 코드를 바꾸는 커밋마다 `APP_VERSION`의 세 번째 숫자를 1 올리고 버전 이력을 적는다. `MIN_COMPATIBLE_VERSION`은 공유 시트 쓰기 방식이 호환되지 않게 바뀔 때만 올린다.
- **개발 PC:** 운영 시트에 연결된 PC에서 푸시하지 않은 더 높은 버전을 실행하면 다른 PC들에 새 버전 안내가 뜬다. `MIN_COMPATIBLE_VERSION`까지 올린 상태였다면 다른 PC들의 쓰기도 멈춘다.
- **Google 읽기 한도:** 같은 계정의 모든 PC가 분당 60회 읽기 한도를 함께 쓴다. 요청 수를 크게 줄였지만, 대량 작업이 겹치면 잠깐 429 오류가 날 수 있다.
- **주소 검색용 키:** 「설정 › 연동」에서 등록하면 비공개 공유 시트의 「설정」 탭 `kpost_postcode_regkey` 행에 저장된다. 시트 열람 권한이 있는 계정은 키 값을 볼 수 있다. 각 주소 검색·우편번호 조회가 최신 키를 읽으므로 Google Sheets 읽기가 한 번 추가된다. 전용 키가 비어 있으면 기존 겸용 키를 사용한다. 시트를 읽지 못할 때는 기존 로컬 키로 조회하거나 연결 오류를 표시한다.
- **안내 끄기:** 「새 버전 안내 무시」를 켠 PC는 업데이트를 놓치기 쉽다.
- **브랜치 시험:** `feat/order-panel`은 버전을 올린 채(`2026.11.17.6`부터) 커밋한다. 운영 시트에 연결된 PC에서 실행하면 다른 PC에 새 버전 안내가 뜨지만, `main`에 합치기 전에는 Pull 해도 받을 것이 없으니 안내를 닫으면 된다. `MIN_COMPATIBLE_VERSION`은 올리지 않았으므로 쓰기는 막히지 않는다.
- **다음 동작 강조:** 주문·발송 탭은 주문 불러오기 → 우체국 접수 엑셀(Ctrl+E, 하이제니스 폼) → 송장 불러오기 → 접수목록 순서로 강조 버튼을 옮긴다. 우체국 접수 엑셀을 만든 기록은 앱 안에만 있어서, 엑셀을 다른 방법으로 만들었거나 앱을 다시 켜면 강조가 「우체국 접수 엑셀」에 머문다(동작은 막지 않는다). 접수목록은 하루치를 내보내는 기능이라 여러 스토어를 이어서 처리할 때는 마지막 묶음 뒤에 한 번만 누르면 된다.
- **송장 매칭 요약:** ②의 「송장 매칭 m/n」은 등기번호가 있는 송장 행 n건 중 주문과 매칭된 행 m건이다(주문 건수가 아니다). 한 주문에 송장이 둘이면 주문 건수보다 n이 클 수 있다. 지마켓·11번가는 일괄발송 파일 생성 대상이 아니어서 매칭 수 없이 건수만 나온다.
- **스토어 로고:** `image/`에 11번가 로고 파일이 없어 11번가는 글자 배지로 그린다. 로고 파일을 넣으면 `ui/order_ship_panel.py`의 `STORE_LOGO_FILES`에 이름을 추가한다.
- **끌어다 놓기:** 끌어다 놓기는 Linux 화면 없는 환경에서 끌기 이벤트를 직접 보내 확인했다. Windows 탐색기·Outlook 첨부에서 끄는 경우(첨부는 임시 파일 경로로 오거나 파일 경로가 없을 수 있음)는 확인하지 못했다. 파일 경로가 없는 끌기는 받지 않는다(파일 대화상자로 불러오면 된다). 송장 엑셀을 ① 패널에 놓는 식으로 잘못 놓으면 기존 파일명 검사가 거절하고 불러온 주문은 그대로 둔다.
- **주문 미리보기 복사:** 예전에는 미리보기 글을 직접 고친 뒤 복사(Ctrl+C)할 수 있었지만, 표로 바뀐 뒤에는 불러온 그대로의 마크다운만 복사된다. 고칠 내용은 붙여 넣은 곳에서 고친다. 불러온 주문이 없을 때 복사하면 클립보드를 비우지 않고 상태줄에만 알린다.
- **사은품 표기**는 주문 마크다운에서 `🎁: 볼펜 + 박스커터 + 에코백` 형식으로 표시한다. 시험 버전 `2026.11.17.10`에서 저장한 구간별 마크다운 문구는 `2026.11.17.11`부터 읽지 않는다.
- **사은품 집계:** `0.0.7` 이상에서 만든 주문 마크다운에 사은품이 표시된 작업 건을 한국시간 기준으로 기록한다. 세트 하나는 해당 구간에서 한 개로 센다. 이전 기록을 소급하거나 주문 취소·출고 결과를 반영하지 않는다. 설정에서 구간을 바꿔도 기록 당시 금액과 사은품 이름을 보존한다. 묶음에 포함된 원주문이나 배송 정보 자체가 바뀌면 다른 작업 건으로 집계될 수 있다.
- **사은품 기록 동기화:** 공유 시트 연결이 끊기면 `database/gift_history.sqlite3`에 저장해 재시도한다. PC 여러 대가 동시에 같은 건을 올리거나 먼저 불러온 PC가 오프라인이었다면 원본에 같은 기록 키가 남을 수 있다. 앱 집계는 첫 표시 시각의 한 건만 센다. 원본으로 직접 분석할 때도 기록 키별 첫 표시 시각을 사용한다.
- **월별 사은품 엑셀:** 「설정 › 주문·사은품」의 「사은품 이벤트 → 일별 집계 · 엑셀」에서 선택한 연월과 스토어 조건으로 공유 시트에서 읽은 사은품 1~4를 저장한다. 기록이 없는 날은 0으로 표시된다. 화면에 공유 시트 반영 대기 건수가 보이면 반영된 뒤 새로고침해서 저장한다.
- **창 위치 기억:** 창 위치는 PC마다 `database/app_settings.json`에 저장된다. 창이 이상한 곳에 뜨면 앱을 닫고 그 파일의 `main_window_geometry` 항목을 지우면 가운데 기본 크기로 돌아간다.

## 4. 실서비스로 확인하지 못한 것

가짜 API, 모의 화면, 가짜 창으로만 검증했다.

- 우체국 접수 재시도 중복 방지(A5)
- 인쇄 창 확인(A6). 실제 Windows 표준 인쇄 창과 메시지 상자로 판별은 확인했다.
- 네이버 발송 API 행 처리(A7)
- 우체국 포털 로그인 대기(C7a)
- 창 닫을 때 남은 저장(A3)
- 프로필 잠금(B7)
- 버전 기록·차단·새 버전 안내. 모의 시트에서 기존 최소 버전과의 호환성, 두 버전 체계의 쓰기 차단, 새 버전 안내를 검증했다. 운영 시트의 버전 기록은 PC별로 실행한 뒤 확인한다.
- 주소 검색용 키 등록·공유. 모의 시트와 우체국 응답으로 등록 및 다른 PC의 첫 검색을 검증했다. 우체국 HTTPS 주소가 인증 오류를 반환하는 것까지 실서비스에서 확인했다. 실제 우편번호 조회용 키로 운영 시트에 등록하고 다른 PC에서 조회하는 점검이 남아 있다.
- 사은품 일별 집계. 모의 시트와 Windows 오프스크린에서 네 스토어의 마크다운과 기록 수량 일치, 로컬 대기 기록, 중복 제거, 날짜·스토어 필터를 확인했다. 운영 시트의 탭 생성과 여러 PC의 실제 동시 기록은 확인이 남아 있다.
- 월별 사은품 엑셀. Windows 오프스크린에서 월 선택과 파일 생성을 검증했다. 운영 시트 자료를 사용한 내보내기와 실제 Excel에서 열기는 확인이 남아 있다.
- 「설정 › 연동」 Google 인증 오류 표시(D13). 토큰 파일 상태와, 실행 중 오류는 재인증을 묻는 창이 뜰 때와 주문번호 인덱스 폴링(2.5분)이 인증 오류로 실패할 때만 기록한다. 다른 시트 작업이 인증 오류 문구 없이 실패하면 배지가 붙지 않는다. 인증 오류는 재인증·연결 해제·다음 폴링 성공 때 지운다. 실제 만료·철회된 토큰으로는 확인하지 못했다.
- 「설정 › 연동 › API 키」 행(D14). 주소 검색·네이버·쿠팡 행은 공유 「설정」 탭에 값이 있는지만 보이고 키가 실제로 유효한지는 확인하지 않는다(이 PC에서 방금 등록·검증한 경우만 「확인함」). 공유 「설정」 탭을 아직 읽지 않았으면 「연동」 페이지를 처음 열 때 한 번 읽는다(배송추적 탭 진입 때 하던 것과 같은 읽기). 운영 시트로는 확인하지 못했다.
