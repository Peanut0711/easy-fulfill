# GUI 창 크기와 「설정」 탭 개편 계획

작성: 2026-11-18, 기준 커밋 `ebaafce`(앱 버전 `0.0.8`). 「정한 것」 반영. 줄 번호는 이 커밋 기준이며 작업 중 바뀌므로 함수 이름으로 찾는다.

## 목표

1. **창 크기:** FHD(1920×1080) 모니터 기준으로 창을 화면 한쪽에 두었을 때 가로는 화면 폭의 절반 미만이고, 위아래로 여유가 남는 크기로 만든다. 어떤 탭으로 바꿔도 창이 커지지 않게 한다.
2. **「설정」 탭:** 「관리자」·「환경설정」·「DB동기화」 탭과 「API(개발 중)」 메뉴의 진단 항목을 「설정」 탭 하나로 모은다. 상위 탭은 8개에서 6개(주문·발송, 배송추적, 단건 송장, 문서 만들기, 상세페이지, 설정)로 줄어든다.

창 크기를 먼저 바꾸고(A단계), 바뀐 크기 예산에 맞춰 설정 탭을 배치한다(B단계).

## 현재 상태 (측정)

`ebaafce`에서 `MainWindow`를 Windows 플랫폼(맑은 고딕 9pt, 배율 100%)으로 만들어 창을 띄우지 않고 쟀다. 단위는 Qt 논리 픽셀이다.

| 항목 | 값 |
|---|---|
| `.ui` 기본 창 크기 | 880×740 |
| 창 최소 크기(`minimumSizeHint`) | **706×806**: 기본 높이 740보다 커서 실제 창은 처음부터 806 높이로 뜬다 |
| 메뉴바 / 탭바 / 상태바 높이 | 36 / 24 / 29 |

탭별 최소 크기(`minimumSizeHint`). `QTabWidget`의 최소 크기는 모든 탭 중 가장 큰 값이므로, 한 탭만 커도 창 전체 최소 크기가 커진다.

| 탭 | 최소 폭×높이 | 비고 |
|---|---|---|
| 주문·발송 `tab` | 661×184 | 좌우 스플리터(① 주문 / ② 송장) |
| 배송추적 `tab_tracking` | **700**×152 | 가장 넓음: 필터 줄과 버튼 3개 |
| 단건 송장 `tab_quick_invoice` | 412×294 | |
| 문서 만들기 `tab_documents` | 66×66 | 이미 스크롤 영역(D1) |
| 상세페이지 `tab_detail_page` | 606×**600** | 묶음 3개와 작업 로그 |
| DB동기화 `tab_db_sheet_sync` | 444×416 | |
| 관리자 `tab_admin` | 461×**689** | 가장 높음: 창 최소 높이 806의 원인 |
| 환경설정 `tab_2` | 350×326 | |

화면 없는(offscreen) 환경에서는 글꼴이 「Sans Serif」로 바뀌어 값이 다르다(창 최소 크기 784×731, 관리자 632 높이). 그래서 크기 예산은 Windows 플랫폼 측정값으로 정하고, 테스트는 여유를 두고 검사한다.

그 밖의 현재 상태:

- 창 크기·위치를 저장하지 않는다. 매번 `.ui`의 크기(`self.resize(window.size())`, `__init__` 끝)로 화면 가운데에 뜬다.
- `ui/main_window.py`, `ui/main_window_ui.py`는 어디서도 import하지 않는 옛 생성 파일이다. 실제 화면은 `ui/main_window.ui`를 `QUiLoader`로 읽는다. 이 파일들은 고치지 않는다.
- 공유 Google 시트에도 「설정」 탭이 있다. 문서와 대화에서는 **앱 「설정」 탭**과 **공유 시트 「설정」 탭**으로 구분해 적는다.

## 크기 기준

FHD 화면 배율별 작업 영역(작업 표시줄 제외)과 목표 크기는 다음과 같다. 값은 논리 픽셀이며, 괄호 안은 실제 화면 픽셀이다.

| 배율 | 작업 영역(대략) | 기본 창(프레임 제외) | 화면 대비 |
|---|---|---|---|
| 100% | 1920×1032 | **900×800** | 프레임 포함 약 916×839: 폭 48%, 위아래 각 약 96 px 여유 |
| 125% | 1536×826 | 약 721×638 (901×798) | 폭 47%, 높이 81% |
| 150% | 1280×688 | 약 601×526 (902×789) | 최소 크기보다 작아 지금 구조로는 불가. 「정한 것」 참고 |

- **기본 창 크기 공식:** `폭 = min(900, 작업영역폭 × 0.47 − 프레임폭)`, `높이 = min(800, 작업영역높이 × 0.81 − 프레임높이)`. 결과가 최소 크기보다 작으면 최소 크기를 쓴다. 프레임 크기는 첫 표시 전에는 알 수 없어 Windows 11 100%에서 잰 값(좌우 0, 위아래 31)을 쓴다.
- **창 최소 크기 예산: 680×560.** 125% FHD 기본 창(721×638)에 들어간다.
- **탭 내용 예산:** 최소 창에서 메뉴바·탭바·상태바·여백을 빼면 탭 한 장의 최소 크기는 **약 670×440** 이하여야 한다. 이보다 큰 탭은 세로 스크롤 영역에 넣거나 배치를 바꾼다.

## A단계: 창 크기

| 순서 | 작업 | 주요 파일 |
|---|---|---|
| A-1 | 측정 도구와 크기 예산 테스트 | 새 `tools/measure_window_sizes.py`, 새 `tests/test_window_size_budget.py` |
| A-2 | 탭별 최소 크기 줄이기 | `ui/main_window.ui`, `easy-fulfill.py` `_mount_detail_page_tab` |
| A-3 | 기본 크기 계산과 위치 기억 | 새 `shared/window_geometry.py`, `easy-fulfill.py` `__init__`·`showEvent`·`closeEvent` |

### A-1. 측정 도구와 크기 예산 테스트

- `tools/measure_window_sizes.py`: 위 측정을 반복하는 스크립트다. `QT_QPA_PLATFORM=windows`로 창을 띄우지 않고 Google 연결은 막은 채(`tests/test_order_file_state.py`와 같은 방식) 창과 탭별 최소 크기, 탭을 모두 돌아본 뒤의 창 크기를 표로 출력한다. 하위 작업마다 전후 값을 이 도구로 재서 커밋 본문과 `docs/known-risks.md`에 적는다.
- `tests/test_window_size_budget.py`(offscreen, 자식 프로세스):
  - 창 최소 크기와 탭별 최소 크기가 예산 이하인지 검사한다. offscreen 글꼴 차이를 감안해 예산에 10% 여유를 둔다.
  - 모든 탭을 한 번씩 연 뒤에도 창 크기가 그대로인지 검사한다.
  - 처음에는 현재 값(관리자 689 높이, 배송추적 700 폭)으로 실패하는 것을 확인하고, A-2와 B단계를 마치면 통과하게 한다. A-2 커밋에서는 아직 남은 탭(관리자)을 `expectedFailure`나 건너뛰기 목록으로 표시하고, B단계에서 지운다.

### A-2. 탭별 최소 크기 줄이기

- **배송추적 (700 → 670 이하):** 필터 줄(`horizontalLayout_tracking_filter`: 건수, 분류, 검색, 요약)과 버튼 줄(추적 중지, 배송중 새로고침, 폐기/예외 재확인)을 두 줄로 나눈다. 요약 라벨(`label_tracking_summary`)은 남는 폭을 쓰되 최소 폭을 0으로 두고, 잘리면 툴팁으로 원문을 보인다(D3와 같은 방식).
- **상세페이지 (600 → 440 이하):** 탭 내용을 세로 `QScrollArea`에 넣는다(문서 만들기 D1과 같은 방식). 4단계 계획 4-5(상품번호 입력 통합, 로그 접기)를 할 때 높이가 더 줄어든다.
- **주문·발송 (661):** 예산 안이므로 이번에는 바꾸지 않는다. 150% 대응을 하게 되면 다시 본다(「정할 것」).
- **관리자·환경설정·DB동기화:** B단계에서 탭이 없어지므로 A단계에서는 손대지 않는다. 따라서 A단계가 끝나도 창 최소 높이는 관리자 탭 때문에 806으로 남는다. **A-3과 B단계는 같은 브랜치에서 이어서 하고, `main`에는 함께 합친다.**

### A-3. 기본 크기 계산과 위치 기억

- 새 모듈 `shared/window_geometry.py`에 Qt에 의존하지 않는 순수 함수를 둔다:
  - `default_window_size(avail_w, avail_h, frame_w, frame_h, min_w, min_h) -> (w, h)`: 위 공식을 계산한다.
  - `is_restorable(rect, screens) -> bool`: 저장된 위치가 현재 연결된 화면의 작업 영역 안에 일정 부분(예: 제목 표시줄 100×30 px) 이상 걸쳐 있고, 크기가 그 화면 작업 영역 이하인지 확인한다. 모니터를 뺐거나 배율을 바꾼 경우에 창이 화면 밖에 뜨는 것을 막는다.
- `MainWindow.__init__`의 `self.resize(window.size())`를 위 계산으로 바꾼다. `centralwidget`에 `setMinimumSize(680, 560)`을 걸지 않는다. 최소 크기는 내용이 정하고, 예산은 테스트로 지킨다.
- **위치 기억(이 PC만):** 창을 닫을 때 `saveGeometry()` 결과를 로컬 앱 설정(`set_app_setting("main_window_geometry", …)`, base64 문자열)에 저장한다. 다음 실행 때 `is_restorable`이면 `restoreGeometry`로 되살리고, 아니면 기본 크기로 작업 영역 가운데에 띄운다. 최대화 상태도 함께 저장된다.
  - 저장은 `closeEvent`에서 한다. `main()`이 `os._exit`로 끝나므로 `closeEvent` 안에서 동기로 저장해야 한다. 기존 닫기 저장 코드(`tests/test_close_flush.py`가 검사하는 부분)와 같은 자리에 둔다.
  - 공유 시트에는 쓰지 않으므로 `MIN_COMPATIBLE_VERSION`은 올리지 않는다.
- 함수 테스트: 100%·125%·150% 작업 영역에서 기본 크기를 계산하고, 화면 밖이나 화면보다 큰 저장값을 거절하는지 검사한다.

**A단계 완료 기준:** 100% FHD에서 처음 실행한 창이 프레임 포함 폭 960 미만, 높이 약 840이고 위아래 여유가 있다. 창을 옮기고 닫았다 다시 열면 같은 자리에 뜬다. 배송추적과 상세페이지의 최소 크기가 예산 안에 든다.

## B단계: 「설정」 탭

### 구성

왼쪽에 분류 목록(`QListWidget`, 폭 약 120), 오른쪽에 분류별 페이지(`QStackedWidget`)를 둔다. 페이지마다 세로 `QScrollArea`에 넣고 내용 최대 폭은 약 560이다. 2열 배치 대신 이 구조를 쓰는 이유는, 125% 배율의 좁은 창(약 706 폭)에서도 한 열로 읽히고 페이지가 짧아 스크롤이 거의 없기 때문이다.

```
┌ 설정 ───────────────────────────────────────────────────┐
│ ▸ 연동      │  Google Sheets                  ✓ 연결됨   │
│   알림      │   [재인증] [인증 폴더] [공유 시트 열기]  [연결 해제] │
│   배송추적  │  API 키 · 전원 공유                         │
│   주문·사은품│   우체국 종추적      ✓ 유효함        [변경]   │
│   DB 동기화 │   우체국 주소 검색   ✓ 등록됨        [변경]   │
│   프로그램  │   네이버 커머스      ✗ 미설정        [등록]   │
│             │   쿠팡 WING          ✓ 등록됨        [변경]   │
└─────────────┴─────────────────────────────────────────────┘
```

| 분류 | 내용 | 원래 위치 |
|---|---|---|
| **연동** | Google Sheets 상태·재인증·인증 폴더 열기·연결 해제, 「공유 시트 열기」(바로가기 메뉴 `act_db`와 같은 동작), API 키(우체국 종추적, 우체국 주소 검색, 네이버, 쿠팡) | 관리자 |
| **알림** | 슬랙 Webhook. 「이 PC」: 위험 일일 알림·테스트, 미답변 문의 자동 조회·지금 확인, 문의 알림 상태. 「전원 공유」: 문의 알림 시간대 | 관리자 |
| **배송추적** | 「전원 공유」: 위험 판정 기준(허브·수거누락·이동·도서산간 2×2), 자동 새로고침 간격 | 관리자 |
| **주문·사은품** | 「전원 공유」: 주문번호 시작값(스토어별)·다시 읽기·되돌리기·동기화 상태, 사은품 구간 설정·일별 집계·엑셀 | 환경설정, 관리자 |
| **DB 동기화** | 이전 DB동기화 탭 내용 전체(대상 체크, 파일 표시·직접지정, 테스트 모드, 상세 로그, 새로고침·실행, 결과 로그) | DB동기화 탭 |
| **프로그램** | 「이 PC」: 버전, 새 버전 안내 무시. 「확인·진단 (실제 동작 없음)」: API 메뉴의 진단 9개 항목을 버튼 목록으로 | 환경설정, API 메뉴 |

### 표시 규칙

- **적용 범위:** 묶음 제목 뒤에 `· 전원 공유` 또는 `· 이 PC`를 붙인다. 지금처럼 「(전원 공유)」·「(관리자)」·툴팁 안 설명으로 제각각 쓰지 않는다. 한 묶음 안에 둘이 섞이면(미답변 문의 알림) 묶음을 나눈다.
- **상태:** 4단계 계획 4-1의 `set_status(label, kind, text, detail)`로 ✓(초록)·!(주의)·✗(빨강)·회색(확인 중)을 표시한다. 4-1이 아직 없으면 B단계 안에서 먼저 만든다. 긴 오류는 첫 줄만 보이고 원문은 툴팁에 둔다.
- **분류 목록 배지:** 연동에 문제가 있으면(Google 인증 실패, 키 확인 실패) 분류 이름 뒤에 `✗`를 붙여 다른 탭에서 왔을 때도 보이게 한다.
- **연결 해제:** 위험 버튼 모양(`set_button_role(…, "danger")`)으로 오른쪽 끝에 떨어뜨린다. Google 인증 안내 문구(`label_google_auth_tip`)는 인증 오류일 때만 보인다.
- 탭 이름은 「⚙ 설정」으로 한다(4단계 4-2의 ⚙ 표시를 이 탭 하나에만 적용).

### 고칠 곳

- **위젯 이름은 유지한다.** `.ui`에서 묶음을 새 페이지로 옮기되 `objectName`(`label_google_auth_status`, `pushButton_cfg_*`, `groupBox_order_index`, `checkBox_ignore_version_update`, `pushButton_db_sync_*`, `checkBox_db_sync_*` 등)은 바꾸지 않아 `self.ui.<이름>`으로 연결하는 코드를 그대로 쓴다.
- **송장추적 설정:** `_build_admin_tracking_settings`는 지금 `widget_admin_tracking` 한 곳에 슬랙(`build_admin_slack_controls`)·문의 알림·위험 기준(`build_admin_risk_controls`)을 차례로 넣는다. 두 빌더가 이미 `outer` 레이아웃을 받으므로 「알림」 페이지와 「배송추적」 페이지의 레이아웃을 각각 넘기도록 나눈다. `tracking/controller.py`의 `build_admin_slack_controls`에서 「이 PC」와 「전원 공유」 묶음 구분만 고친다.
- **API 키 상태:** `label_settings_api_status` 한 줄(`_update_status_displays`)을 키별 행으로 바꾼다.
  - 「문의 키: …」는 키 상태가 아니라 문의 폴링 결과(`_naver_inquiry_status_text`, 예: 「미답변 3건 · 새 알림 없음」)다. 「알림」 페이지의 문의 알림 상태로 옮긴다.
  - 네이버·쿠팡·주소 검색 키는 지금 따로 상태를 계산하지 않는다. 이미 읽어 둔 설정값으로 「등록됨/미설정」만 보인다. 새 API 호출이나 시트 읽기를 늘리지 않는다.
- **탭 전환 갱신:** `_on_main_tab_changed`의 `tab_2`(Google 인증 상태)·`tab_db_sheet_sync`(파일 경로) 분기를 「설정」 탭 진입 시와 분류 페이지 전환 시로 옮긴다. 페이지 객체 이름으로 분기한다.
- **탭 순서:** `_apply_tab_order`의 목록을 `tab`, `tab_tracking`, `tab_quick_invoice`, `tab_documents`, `tab_detail_page`, `tab_settings` 6개로 바꾸고 독스트링의 「7개」도 고친다. 빈 탭이 된 `tab_admin`·`tab_2`·`tab_db_sheet_sync`는 `.ui`에서 지운다.
- **API 메뉴:** 진단 9개(`act_epost_test_receipt`, `act_epost_portal_diagnostic`, `act_epost_portal_lookup`, `act_epost_portal_print_popup`, `act_epost_portal_oz_viewer`, `act_epost_portal_output_confirm`, `act_epost_portal_reprint_popup`, `act_epost_portal_reprint_oz_viewer`, `act_epost_oz_print_dialog`)는 메뉴에서 빼고 「프로그램」 페이지에 같은 `QAction`을 부르는 버튼으로 둔다. 메뉴에는 `act_api_load`, `act_epost_portal_login`, `act_epost_print_targets`와 구분선 아래 실제 동작 4개(`act_dispatch`, `act_epost_real_receipt`, `act_epost_actual_print`, `act_epost_batch_actual_print`)만 남긴다. 이것으로 4단계 4-3을 대신한다. 실제 동작 4개의 확인 창은 그대로 두고, 「No」면 호출이 없음을 테스트로 고정한다.
- **고칠 테스트:**
  - `tests/test_version_gate.py:347`: `tab_2` 안의 `checkBox_ignore_version_update` → `tab_settings` 안으로.
  - `tests/test_order_preview.py:320`: `tab_admin`이 `pushButton_gift_history`를 품는지 → `tab_settings`로.
- **문서:** `docs/app-version-update-guide.md`와 `docs/known-risks.md`에서 「환경설정 「프로그램 버전」」, 「관리자 「사은품 이벤트 → …」」처럼 탭 위치를 적은 곳을 「설정 › 프로그램」, 「설정 › 주문·사은품」으로 고친다(`grep -n "환경설정\|관리자" docs/*.md`). 버전 이력 표의 지난 항목은 당시 기록이므로 고치지 않는다. 「새 버전 안내 무시」 위치가 바뀌므로 `docs/app-version-update-guide.md`의 안내 절과 파일 표도 같은 커밋(B-1)에서 고친다.

### 하위 작업과 커밋

| 순서 | 작업 |
|---|---|
| B-1 | 「설정」 탭 뼈대(분류 목록·페이지·스크롤)와 기존 묶음 이동(이름 유지). 관리자·환경설정·DB동기화 탭 제거, 탭 순서·탭 전환 갱신, 테스트 두 곳 수정. 크기 예산 테스트가 모두 통과 |
| B-2 | 적용 범위 표시 통일, 알림 묶음 나누기, 상태 배지(`set_status`), 분류 목록 배지 |
| B-3 | API 키 키별 행, 「문의 키」 문구 이동, 연결 해제 위험 버튼, 인증 안내 오류 시에만 표시 |
| B-4 | 진단 항목을 「프로그램」 페이지로 이동, API 메뉴 정리, 실제 동작 확인 창 테스트 |
| B-5 | DB 동기화 페이지 다듬기(4단계 4-6: 실행 강조, 테스트 모드 띠, 파일 표시) |

**B단계 완료 기준:** 상위 탭이 6개이고, 옛 탭에 있던 모든 버튼·입력이 「설정」에서 같은 동작을 한다. 창 최소 크기가 680×560 이하이고(Windows 측정), 모든 탭과 설정 페이지를 오가도 창 크기가 바뀌지 않는다.

## 4단계 계획과의 관계

`docs/gui-stage4-structure-style-plan.md`와 겹치는 부분은 이 문서를 따른다.

| 4단계 항목 | 이 계획에서 |
|---|---|
| 4-1 공통 스타일 | 그대로. B-2 전에 끝낸다 |
| 4-2 관리 탭 ⚙ 표시 | 「설정」 탭 하나에만 적용 |
| 4-3 API 메뉴 정리 | B-4로 대신함 |
| 4-4 관리자·환경설정 2열 | 폐기. 「설정」 탭 분류 구조로 대신함 |
| 4-5 상세페이지 정리 | 그대로. A-2의 스크롤 영역 위에서 진행 |
| 4-6 DB동기화 정리 | B-5로 옮겨 「설정 › DB 동기화」 페이지에 적용 |

권장 순서: A-1 → A-2 → A-3 → 4-1 → B-1 → B-2 → B-3 → B-4 → B-5 → 4-5.

## 하지 않을 것

- 탭·메뉴를 숨기거나 잠그기(관리자 모드, PIN).
- 공유 시트 쓰기 방식 변경. 따라서 `MIN_COMPATIBLE_VERSION`은 올리지 않는다. 창 위치는 로컬 앱 설정에만 저장한다.
- 팝업 창 크기(상세 HTML 편집기 1280×760, 이미지 보기 1024×768 등) 변경. 필요하면 다음 작업으로 둔다.
- 우체국 실제 접수·인쇄, 네이버 발송처리 API, 쿠팡 WING 저장, 운영 Google 시트 쓰기 실행.

## 검증

- 하위 작업마다 `tools/measure_window_sizes.py`로 창·탭 최소 크기를 수정 전후로 재서 커밋 본문에 적는다.
- offscreen으로 바뀐 탭과 설정 페이지를 수정 전후로 캡처(`grab()`)해 비교한다.
- 전체 테스트 `python -m unittest discover`가 수정 전과 같은 결과(새 테스트 제외)인지 확인한다.
- Windows 실제 화면에서 100%·125% 배율로 기본 창 크기, 위치 기억, 모든 탭 전환 시 크기 유지를 확인한다. 화면 배율은 Windows 설정에서 바꾸거나 `QT_SCALE_FACTOR=1.25`로 흉내 낸다.

## 진행 규칙

`AGENTS.md`를 따른다. 앱 코드를 바꾸는 커밋마다 `APP_VERSION` 세 번째 숫자를 올리고 버전 이력을 적는다. `docs/known-risks.md` 「작업별 기록」의 「D. 화면 배치」에 이어서 기록한다. A단계만 합치면 창 최소 높이가 그대로 806이라 목표를 채우지 못하므로, 작업 브랜치(`feat/window-settings`)에서 A·B단계를 마치고 한 PC에서 확인한 뒤 `main`에 합친다.
